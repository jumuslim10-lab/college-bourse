# Деплой на Railway

Railway — облако, которое само собирает и запускает проект из GitHub. Для этого проекта подходит
лучше VPS: не нужно администрировать сервер, обновление происходит по `git push`, переменные и
логи — в веб-интерфейсе.

## Главное условие

**Регион сервиса — Singapore.** База живёт в Supabase (регион Singapore), и если сервис окажется
в США или Европе, каждый запрос снова будет ходить через полмира (~200 мс вместо 1–5 мс).
Регион сервиса в Railway меняется на месте, без пересоздания проекта.

## Сколько стоит

Railway тарифицирует по секундам: память $10 за ГБ/мес, CPU $20 за vCPU/мес.

Наш бот в простое держит ~70–100 МБ памяти и почти не тратит CPU, то есть **примерно $1–1,5 в месяц**:

- тариф **Free** даёт $1 кредита в месяц — может хватить впритык;
- тариф **Hobby** ($5/мес) включает $5 расхода — наш бот укладывается с большим запасом,
  и есть история логов за 7 дней вместо 3.

Аренда VPS в Сингапуре стоит примерно столько же ($3.5–6), но требует ручной настройки.
Официальные данные: [Pricing](https://railway.com/pricing), [Regions](https://docs.railway.com/deployments/regions).

## Шаги

1. Зайти на **railway.com** → **Login** → войти через GitHub (карта не нужна для триала).
2. **New Project** → **Deploy from GitHub repo** → выбрать `jumuslim10-lab/college-bourse`.
   Репозиторий публичный, доступы выдавать не нужно. Railway увидит `Dockerfile` и соберёт образ сам.
3. В сервисе открыть **Variables** и добавить четыре переменные (файл `.env` на сервере не нужен):

   ```
   BOT_TOKEN=<токен от @BotFather>
   ADMIN_IDS=<твой tg_id>
   DB_BACKEND=postgres
   DATABASE_URL=<строка подключения Supabase>
   ```

4. **Settings → Region → Singapore** (в коде региона это `asia-southeast1`).
5. **Deploy** → открыть **Logs** и дождаться строк:

   ```
   Postgres подключён: Postgres: aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres
   Бот запущен. База: Postgres: ...
   Run polling for bot @SMITX_bot
   Health-ответ слушает порт <PORT>
   ```

6. **Остановить локальный бот** на компьютере (закрыть окно или `Ctrl+C`): Telegram отдаёт
   обновления только одному экземпляру, иначе в логах будет `409 Conflict`.

## Обновление кода

Достаточно отправить изменения в GitHub — Railway пересоберёт и перезапустит сервис сам.
Никаких скриптов обновления не нужно.

## Если что-то не так

| Симптом в логах | Причина и что делать |
|---|---|
| `409 Conflict` | Работает второй экземпляр: останови локальный бот или старый сервис |
| `Telegram отклонил токен` | Неверный `BOT_TOKEN` в Variables |
| `Не удалось подключиться к Postgres` | Ошибка в `DATABASE_URL`; пароль с символами должен быть закодирован (`$` → `%24`, `%` → `%25`) |
| `tenant/user ... not found` | Строка подключения от другого проекта Supabase |
| Сервис перезапускается по кругу | Смотри лог: обычно это опечатка в переменных |
