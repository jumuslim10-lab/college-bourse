## Заход 2 (агент DeepSeek): UI, логика, изоляция, тесты

Сделано:

1. **Запросы.** `list_active`, `count_active`, `category_counts`, `count_all_active`,
   `search_active`, `stats`, `active_user_ids` получили необязательный `community_id`
   (`None` = общий вид). Условие в SQL: `(? IS NULL OR community_id = ?)`.
2. **Привязка объявлений.** `create_listing(..., community_id=None)`; `services.submit_listing`
   передаёт площадку автора в обеих ветках (авто-отклонение и обычная отправка).
3. **Бизнес-логика** в `bot/services.py`: `normalize_community_code`, `is_valid_community_code`,
   `parse_start_payload`, `can_view_community`, `create_community`, `join_community`,
   `needs_community_switch`. Валидация кода (3–32, латиница/цифры/дефис, без дефиса на концах),
   проверка дубликата, обязательный город.
4. **Инвайт-ссылки.** `/start <код>` привязывает студента к площадке; обработка «площадка не
   найдена» и «площадка отключена».
5. **UI.** `bot/handlers/communities.py` + `keyboards.communities_kb`: список площадок со
   счётчиками, отметка текущей, пункт «🌍 Все площадки». Кнопка «🏢 Площадки» добавляется в меню
   только при 2+ активных площадках (`main_menu(show_communities)`), поэтому одиночная площадка
   работает как раньше.
6. **Изоляция.** `can_view_community` вызывается в карточке объявления, раскрытии контакта и
   отметке сделки → «Это объявление с другой площадкой».
7. **Админка.** Раздел «🏫 Площадки»: создание через FSM `CommunityForm` (код → название → город),
   включение/выключение по нажатию, счётчики объявлений и людей, готовая инвайт-ссылка
   (username бота кешируется), статистика по каждой площадке в `/stats` и в админке.
8. **Рассылки.** `broadcast(..., community_id=None)`; дайджест считается и рассылается отдельно
   по каждой площадке, чтобы объявления не перетекали между колледжами.
9. **Правило общего пула.** `db.adopt_unassigned`: первая созданная площадка забирает к себе всех
   пользователей и объявления без площадки — иначе после появления площадки у студентов
   «пропали» бы все старые объявления. Вторая и последующие площадки никого не забирают.
10. **Миграция индекса.** `CREATE INDEX IF NOT EXISTS` не обновляет существующий индекс, поэтому
    `migrate()` проверяет `sqlite_master` и пересобирает `idx_listings_cat`, если в нём нет
    `community_id`.
11. **Тесты.** `tests/test_communities.py` — 14 тестов. Итого в проекте **42 теста**, линтер чист.
    `test_wiring` обновлён на 7 роутеров.

### Что было исправлено по ходу

- **Авто-отклонение теряло площадку.** Замена в `submit_listing` применилась только к ветке
  авто-фильтра: объявления, прошедшие фильтр, создавались без `community_id`. Поймано тестом
  `test_listing_inherits_author_community`, исправлено.
- **Несогласованная семантика NULL.** `can_view_community` считал объявления без площадки
  видимыми всем, а SQL их в площадке не показывал. Приведено к одному правилу: общий пул виден
  только в общем виде, а первую площадку он «догоняет» через `adopt_unassigned`.
- **Строка пользователя — снимок.** Тесты падали, потому что `user["community_id"]` читался
  из устаревшей строки после `set_user_community`; в хелперы добавлена `bind_community`,
  возвращающая обновлённую строку.

### Удалено намеренно

- `CODE_EXAMPLES.md` и `QUICKSTART.md` первого захода. Они описывали несуществующий код:
  `list_active`, возвращающий кортеж `(listings, total)`, метод `search_listings` (в проекте он
  `search_active`), асинхронную pytest-фикстуру `db: Database` (в проекте тесты идут через
  `run(scenario())` и `open_db`), `ALL_ROUTERS` как список (в проекте — кортеж). Копирование этих
  фрагментов сломало бы рабочий бот, поэтому инструкции заменены на фактическое описание в README.
